# RAG (Retrieval-Augmented Generation) 시스템

## 기본 개념
RAG = 데이터베이스에서 정보를 찾아와서 AI에게 알려주는 시스템

## 작동 원리
1. 사용자 질문 입력
2. DB에서 관련 정보 검색 (Retrieval)
3. 검색된 정보 + 질문을 AI에 전달
4. AI가 정보를 바탕으로 답변 생성 (Generation)

## 일반적인 RAG의 구성
- 벡터 데이터베이스 (Pinecone, Weaviate, Milvus 등)
- 임베딩 모델 (OpenAI, Hugging Face)
- LLM (Claude, GPT-4 등)
- 검색 엔진

## 일반적인 RAG의 문제
1. **벡터 DB 필요** → 비싸고 복잡함
2. **복잡한 임베딩 과정** → 유지보수 어려움
3. **서버 비용 필요** → 지속적인 운영 비용
4. **응답 속도** → 검색 + 임베딩 + 생성 시간 필요

## Obsidian 기반 경량 RAG의 장점
- ✓ 벡터 DB 불필요
- ✓ 폴더 구조 + 마크다운만으로 충분
- ✓ 로컬 저장 (클라우드 비용 없음)
- ✓ AI와 100% 호환
- ✓ 빠른 응답 속도
- ✓ 토큰 효율성 (4배~10배 비용 절감)

## 사용 사례
- 개인 지식 관리
- 팀 내 정보 공유
- 프로젝트 문서 관리
- 학습 자료 정리
- 비즈니스 인사이트 축적

## 핵심: 구조화된 정보의 가치
RAG의 진짜 가치는 DB가 아니라, **정보가 얼마나 잘 정제되고 구조화되었는가**에 있다.
- 정제된 100개 파일 > 미정제 10,000개 파일
- 토큰 효율성도 높고 정확도도 높음
