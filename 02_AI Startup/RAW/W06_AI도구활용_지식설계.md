# W06: AI 도구 활용 - 지식을 설계한다

## 강의 내용 요약

### 문제: 텍스트의 홍수
- AI와 함께 일하다 보니 텍스트가 무한정 생성됨
- 코드, 아이디어, 수정 사항, 시도한 것들이 흩어져 있음
- 어떤 파일이 중요한지 모름
- 찾기 어려움

### 해결책: RAG 시스템 설계
일반적인 RAG의 문제:
- 벡터 데이터베이스 필요
- 복잡한 임베딩 과정
- 서버 비용 필요

Obsidian 방식 (경량 RAG):
- 벡터 DB 불필요
- 폴더 구조 + 마크다운만으로 충분
- 로컬 저장 (클라우드 비용 없음)
- AI와 100% 호환

### 3단계 폴더 구조

1. **Raw 폴더** (창고)
   - 웹에서 수집한 기사, 논문, 메모
   - 미정제 데이터를 그냥 던져놓음
   - 정제할 필요 없음
   - 양이 많아도 OK

2. **Wiki 폴더** (전시실)
   - Claude Code가 Raw를 분석해서 정리
   - 주제별로 깔끔하게 구성된 문서
   - 정보 압축 (중복 제거)
   - 논리적 연결

3. **Master Index.md** (안내 데스크)
   - 모든 Wiki 문서의 목록
   - AI의 길잡이

### AI가 질문을 받으면
1. Index 읽기 (가장 먼저)
2. 관련 Wiki 찾기
3. 필요하면 Raw 원본 읽기

### 계층적 탐색의 강점
- 모든 파일을 다 읽지 않아도 됨
- 목록 → 요약 → 원본
- 필요한 만큼만 깊이 들어감
- 토큰 절약
- 속도 향상
- 정확도 향상 (노이즈 없음)

### 토큰 효율성
일반적인 RAG:
- 질문 하나 당 ~10,000 토큰
- 200개 문서 다 로드

Obsidian 방식:
- Index 읽기: 100 토큰
- Wiki 선택: 500 토큰
- Raw 접근: 필요시만 2,000 토큰
- 합계: 최대 2,500 토큰
- 결과: 4배~10배 비용 절감

### 폴더별 전용 CLAUDE.md
- 전체 Vault: 일반 규칙 1개
- 각 카테고리 폴더: 별도의 CLAUDE.md
- 같은 Vault에 여러 전문가 고용 가능

예:
- 유튜브 폴더: "너는 콘텐츠 크리에이터 전문가야"
- 연구 폴더: "너는 논문 분석 전문가야"


### 최소한주의의 원칙
- AI가 무한정 생성하니까, 필요한 것만 남기자
- Raw 100개 파일 중 10개만 선택
- 결과: 동기화 빨라짐, 검색 빨라짐, 머리 가벼워짐, 토큰 비용 절감

### Claude Code와의 동시 작업
화면을 양쪽으로 나눔:
- 왼쪽: VS Code (코드) - 웹 서비스 구현, 파일 생성/수정
- 오른쪽: Obsidian (기획) - 기능 명세 작성, API 스펙 정리

실시간 동기화:
- 코드 수정 → 즉시 Obsidian에 반영
- 기획 수정 → 즉시 코드에 반영

## 핵심 메시지
이것은 전문성의 축적 전략이다. 이것이 없는 전문가는 같은 실수를 반복하고, 과거 아이디어를 잊고, 매번 처음부터 시작한다. 이것이 있는 전문가는 과거의 실수로 배우고, 과거의 성공을 재활용하고, 더 빠른 의사결정을 한다.
