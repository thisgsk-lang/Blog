# 개인 지식 시스템 구축 전략

## 배경: 텍스트의 홍수

### 문제점
AI와 함께 작업하면서:
- ❌ 코드, 아이디어, 수정사항이 무한정 생성됨
- ❌ 파일들이 흩어져 있음
- ❌ 어떤 파일이 중요한지 모름
- ❌ 필요한 정보를 찾기 어려움
- ❌ 같은 실수를 반복함

### 해결 필요성
**빠르게 생성되는 텍스트를 관리하는 시대**
→ 시스템이 없으면 정보의 노예가 됨

---

## 솔루션: 경량 RAG 시스템 (Obsidian)

### 일반적인 RAG의 문제
| 문제 | 이유 |
|------|------|
| 벡터 DB 필요 | 비싸고 복잡 |
| 복잡한 임베딩 | 유지보수 어려움 |
| 서버 비용 | 지속적 운영 비용 |
| 느린 속도 | 여러 단계 거침 |

### Obsidian 방식의 장점
- ✓ 벡터 DB 불필요
- ✓ 폴더 구조 + 마크다운만으로 충분
- ✓ 로컬 저장 (클라우드 비용 없음)
- ✓ AI와 100% 호환
- ✓ 4배~10배 비용 절감
- ✓ 더 빠른 응답
- ✓ 더 정확한 답변

---

## 3단계 폴더 구조

도서관 운영에 비유하면:

### 1단계: RAW 폴더 (창고)
**역할**: 미정제 데이터 수집소

**특징**:
- 웹에서 수집한 기사, 논문, 메모
- 아이디어 메모, 사용자 피드백 스크린샷
- 정제할 필요 없음
- 그냥 저장만 함
- 양이 많아도 OK

**원칙**: 자유롭게 저장, 형식 무관, 중복 허용

### 2단계: WIKI 폴더 (전시실)
**역할**: 정제된 지식 저장소

**특징**:
- Claude Code가 RAW를 분석해서 정리
- 주제별로 깔끔하게 구성된 문서
- 정보 압축 (중복 제거)
- 논리적 연결
- AI 친화적 구조

**과정**:
```
Raw "AI 에이전트 논문 5개, 기사 3개, 메모 2개"
    ↓
Claude 분석
    ↓
Wiki "AI 에이전트란 무엇인가" (1개 문서)
```

### 3단계: Master Index.md (안내 데스크)
**역할**: 모든 문서의 길잡이

**역할**:
- 모든 WIKI 문서의 목록
- AI의 첫 번째 진입점
- 계층적 구조
- 검색을 위한 네비게이션

---

## AI가 질문을 받으면 하는 일

```
사용자 질문
    ↓
1단계: Master Index 읽기
   - 목차 확인 (100토큰)
   - 관련 섹션 찾기
    ↓
2단계: 관련 WIKI 선택
   - 해당 문서 로드 (500토큰)
   - 핵심 내용 파악
    ↓
3단계: 필요하면 RAW 원본 접근
   - 세부 정보 필요시만 (2,000토큰)
   - 출처 확인
    ↓
답변 생성
```

### 계층적 탐색의 강점
- ✓ 모든 파일을 다 읽지 않아도 됨
- ✓ 목록 → 요약 → 원본 구조
- ✓ 필요한 만큼만 깊이 들어감
- ✓ **토큰 절약**
- ✓ **속도 향상**
- ✓ **정확도 향상** (노이즈 없음)

### 토큰 효율성

**일반적인 RAG:**
- 질문 하나 당 ~10,000 토큰
- 200개 문서 모두 로드

**Obsidian 경량 RAG:**
- Index 읽기: 100 토큰
- Wiki 선택: 500 토큰
- Raw 접근: 필요시만 2,000 토큰
- **합계: 최대 2,500 토큰**
- **결과: 4배~10배 비용 절감**

## 폴더별 전용 CLAUDE.md

### 구조
```
Vault/
├── CLAUDE.md (전체 일반 규칙)
├── 유튜브/
│   └── CLAUDE.md (유튜브 전용)
├── 연구/
│   └── CLAUDE.md (연구 전용)
└── AI/
    └── CLAUDE.md (AI 전용)
```

### AI의 인격이 바뀐다

**유튜브 폴더의 CLAUDE.md:**
```
"너는 콘텐츠 크리에이터 전문가야.
최신 AI 트렌드를 요약해주고,
썸네일 카피를 써줘."
```

**연구 폴더의 CLAUDE.md:**
```
"너는 논문 분석 전문가야.
논문의 핵심을 요약하고,
비즈니스 모델을 분석해줘."
```

### 결과
- 같은 Vault에 여러 전문가 고용 가능
- 각 폴더마다 다른 역할 정의
- 동일 정보도 다른 관점에서 분석

## Claude Code와의 동시 작업

### 워크플로우

**화면을 양쪽으로 나눔:**
```
왼쪽: VS Code (코드)        오른쪽: Obsidian (기획)
├─ 웹 서비스 구현         ├─ 기능 명세 작성
├─ 파일 생성, 수정        ├─ API 스펙 정리
└─ 기술 구현              └─ 진행 상황 기록
```

### 실시간 동기화
- 코드 수정 → 즉시 Obsidian에 반영
- 기획 수정 → 즉시 코드에 반영

### 효과
- 한 주 동안 웹 서비스 완성 가능
- 기획과 구현이 동시에 진행
- 변경사항 추적 용이

## 최소한주의의 원칙 (정제의 핵심)

### 문제
AI가 무한정 생성하니까, **필요한 것만 남겨야 한다**

### 실행 방식
- Raw 100개 파일 중 **10개만 선택**
- 나머지 90개는 검토 후 삭제

### 결과
| 항목 | 효과 |
|------|------|
| 동기화 속도 | ↑ 빨라짐 |
| 검색 속도 | ↑ 빨라짐 |
| 토큰 비용 | ↓ 절감 |
| 머리 상태 | ↑ 가벼워짐 |

### 비용 분석
- 미정제: 10,000개 파일 = 엄청난 비용
- 정제: 100개 파일 = 1/100 비용

## 핵심 메시지

### 1. 구조가 중요하다
- 명확한 폴더 구조
- 일관된 네이밍
- 계층적 조직

### 2. 정제가 중요하다
- RAW → WIKI 정기적 변환
- 중복 제거
- 논리적 연결

### 3. 네비게이션이 중요하다
- Master Index 유지
- 링크 기반 탐색
- 검색성 최적화

### 결론
**경량 RAG는 복잡한 기술이 아니라, 정보 정제와 구조화의 철학이다.**

## 성공하는 사람의 특징

이 시스템이 있는 전문가:
- 과거의 실수로부터 학습 → **같은 실수 안 함**
- 과거의 성공을 재활용 → **반복 성공**
- 빠른 의사결정 → **시간 단축**
- 깊이 있는 전문성 → **경쟁력 확보**

**이것이 경쟁력이 되는 이유**
