# 경량 RAG 시스템 설계: Obsidian 방식

---

## 문제 정의
AI와 함께 작업하면서 **텍스트의 홍수** 발생:
- 코드, 아이디어, 수정사항이 무한정 생성
- 파일들이 흩어져 있음
- 어떤 파일이 중요한지 불명확
- 필요한 정보를 찾기 어려움

---

## 일반적인 RAG의 한계
| 요소 | 문제점 |
|------|--------|
| 벡터 DB | 복잡하고 비쌈 |
| 임베딩 | 유지보수 어려움 |
| 서버 | 지속적인 운영 비용 |
| 응답속도 | 검색+임베딩+생성 시간 |

---

## 해결책: 경량 RAG (Obsidian)

### 핵심 원칙
- ✓ 벡터 DB 불필요
- ✓ 폴더 구조 + 마크다운만으로 충분
- ✓ 로컬 저장 (클라우드 비용 없음)
- ✓ AI와 100% 호환

### 3단계 폴더 구조

#### 1단계: RAW (창고)
**역할**: 미정제 데이터 수집소
- 웹 기사, 논문, 메모, 스크린샷
- 정제 불필요 (그냥 저장만 함)
- 양 제한 없음

**특징**: 자유로운 형식, 중복 OK, 미완성 OK

#### 2단계: WIKI (전시실)
**역할**: 정제된 지식 저장소
- RAW를 분석해서 정리한 문서
- 주제별 깔끔한 구성
- 중복 제거, 논리적 연결

**특징**: 정제됨, 재사용 가능, 명확함

#### 3단계: Master Index.md (안내 데스크)
**역할**: 모든 문서의 네비게이션
- WIKI 문서 목록
- AI의 첫 번째 진입점
- 검색을 위한 가이드

**특징**: 계층적 구조, 링크 기반 탐색

---

## 계층적 탐색 프로세스

```
AI 질문 받음
    ↓
1. Master Index 읽기 (100토큰)
    ↓
2. 관련 WIKI 찾기 (500토큰)
    ↓
3. 필요시만 RAW 확인 (선택적 2,000토큰)
    ↓
답변 생성
```

---

## 토큰 효율성 비교

### 일반적인 RAG
- 질문당 ~10,000 토큰
- 200개 문서 모두 로드

### Obsidian 경량 RAG
- Index: 100토큰
- Wiki 선택: 500토큰
- Raw 접근: 필요시만 2,000토큰
- **합계: 최대 2,500토큰**
- **결과: 4배~10배 비용 절감**

---

## 구현 전략

### 1. 초기 설정
```
Vault/
├── CLAUDE.md (역할 정의)
├── Master Index.md
├── RAW/
└── WIKI/
```

### 2. 운영 흐름
- **수집**: RAW에 자료 저장 (정제 X)
- **분석**: 주기적으로 RAW 검토
- **정제**: 핵심만 추출해서 WIKI로 정리
- **네비게이션**: Master Index 업데이트

### 3. 메타데이터 자동화
Frontmatter (YAML):
```yaml
---
title: 문서명
date: 작성일
category: 분류
status: 초안/검토/확정
tags: [태그1, 태그2]
---
```

---

## 최소한주의의 원칙

### 핵심 규칙
- **AI는 무한정 생성한다**
- **필요한 것만 남겨야 한다**

### 실행
- Raw 100개 파일 → Wiki 10개 파일만 선택
- 결과: 동기화 빨라짐, 검색 빨라짐, 머리 가벼워짐

### 토큰 비용 절감
- 미정제: 10,000개 파일 = 엄청난 비용
- 정제: 100개 파일 = 1/100 비용

---

## 폴더별 전용 CLAUDE.md

### 구조
```
Vault/
├── CLAUDE.md (일반 규칙)
├── 카테고리1/
│   └── CLAUDE.md (카테고리1 전용)
└── 카테고리2/
    └── CLAUDE.md (카테고리2 전용)
```

### 역할 변경의 예
- **유튜브 폴더**: "너는 콘텐츠 크리에이터 전문가야"
- **연구 폴더**: "너는 논문 분석 전문가야"
- **AI 폴더**: "너는 AI 전략가야"

→ 같은 Vault에 여러 전문가 고용 가능

## Claude Code와의 연동

### 실시간 동기화 워크플로우
```
화면 분할
├─ 왼쪽: VS Code (코드 구현)
└─ 오른쪽: Obsidian (기획 및 기록)
```

### 상호작용
- 코드 수정 → 즉시 Obsidian에 반영
- 기획 수정 → 즉시 코드에 반영

## 성공 요소

### 1단계: 구조 (중요도: ★★★)
- 명확한 폴더 구조
- 일관된 네이밍
- 계층적 조직

### 2단계: 정제 (중요도: ★★★)
- RAW → WIKI 정기적 변환
- 중복 제거
- 논리적 연결

### 3단계: 네비게이션 (중요도: ★★)
- Master Index 유지
- 링크 기반 탐색
- 검색성 최적화
